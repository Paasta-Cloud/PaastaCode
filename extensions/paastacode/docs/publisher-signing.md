# گرفتن امضای ناشر پاستاکد

بررسی منابع: ۲۲ مهر ۱۴۰۵. ناشر فعلاً گواهی ویندوز و عضویت Apple Developer ندارد و تهیهٔ آن‌ها را به مرحلهٔ بعد سپرده است. بسته‌های فعلی بتا بدون امضای ناشرند؛ امضای رسمی شرط تحویل این مرحله نیست. وضعیت بدون امضا باید در صفحهٔ دانلود مشخص باشد.

## ویندوز

برای توزیع EXE، مسیر معمول دریافت گواهی Code Signing از یک مرجع معتبر است. پیش از خرید، پذیرش کشور و هویت حقوقی ناشر، مدارک لازم و امکان امضا در GitHub Actions را از همان مرجع بپرسید. گواهی OV یک گزینه است؛ EV صرفاً برای حذف فوری هشدار SmartScreen توجیه ندارد، چون چنین تضمینی نمی‌دهد. جزئیات گزینه‌ها در [راهنمای مایکروسافت](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options) آمده است.

Azure Artifact Signing هم گزینهٔ امضای ابری است، ولی طبق همین راهنما پذیرش سازمان‌ها به آمریکا، کانادا، اتحادیهٔ اروپا و بریتانیا محدود است. برای ناشر ثبت‌شده در ایران نباید این گزینه را آمادهٔ استفاده فرض کرد.

روند کار: انتخاب مرجع و تأیید پذیرش ناشر؛ احراز هویت؛ دریافت روش نگهداری کلید و دسترسی امضا؛ اتصال روش واقعی به CI؛ امضای نصب‌کننده و فایل اجرایی؛ بررسی امضا، نصب و به‌روزرسانی روی ویندوز. پیش از خرید روشن شود که کلید روی توکن، HSM یا سرویس ابری نگه داشته می‌شود؛ وجود فایل قابل‌صدور PFX را فرض نکنید.

[SignPath Foundation](https://signpath.org/terms) برای پروژه‌های متن‌باز واجد شرایط، گزینهٔ رایگان دارد؛ پذیرش قطعی نیست. شرایط آن اجزای اختصاصی را نمی‌پذیرد. بستهٔ پاستاکد با فونت دارای مجوز یکان باید جداگانه بررسی شود و صرفاً متن‌بازبودن مخزن برای تأیید کافی نیست. درخواست از [فرم رسمی](https://signpath.org/apply) انجام می‌شود؛ هیچ درخواست یا تعهدی از طرف ناشر ثبت نشده است.

## macOS

از [ثبت‌نام رسمی Apple Developer Program](https://developer.apple.com/programs/enroll/) شروع کنید. برای نمایش نام شرکت، ثبت‌نام سازمانی نیاز به شرکت حقوقی، اختیار امضای قرارداد، شمارهٔ D‑U‑N‑S، ایمیل دامنهٔ شرکت، سایت فعال و Apple Account با تأیید دومرحله‌ای دارد. اپل هزینهٔ پایه را سالانه ۹۹ دلار اعلام می‌کند؛ مبلغ محلی ممکن است متفاوت باشد. پذیرش کشور ثبت و امکان پرداخت را پیش از تهیهٔ حساب بررسی کنید.

پس از تأیید عضویت، گواهی Developer ID Application بسازید و برنامه را امضا و notarize کنید. این مسیر برای توزیع خارج از Mac App Store در [شرح رسمی برنامهٔ اپل](https://developer.apple.com/programs/) آمده است. سپس امضا، notarization و نصب و به‌روزرسانی هر دو معماری مک آزموده می‌شوند.

## اتصال به انتشار پروژه

گردش کار `paastacode-release.yml` فعلاً ورودی `signed` و اطلاعات جداگانهٔ ویندوز و مک دارد. مسیر فایل گواهی از `PAASTACODE_WINDOWS_CSC_LINK` یا `PAASTACODE_MAC_CSC_LINK` و رمز آن از متغیر متناظر `CSC_KEY_PASSWORD` خوانده می‌شود. مک همچنین از `PAASTACODE_APPLE_ID`، `PAASTACODE_APPLE_APP_SPECIFIC_PASSWORD` و `PAASTACODE_APPLE_TEAM_ID` استفاده می‌کند. این تنظیم موجود، به معنی پشتیبانی آماده از هر توکن یا سرویس ابری نیست؛ سازگارکردن گردش کار با روش انتخاب‌شده پس از تهیهٔ آن انجام می‌شود.

اطلاعات حساس فقط در Secrets مخزن ناشر یا سامانهٔ امن امضا قرار می‌گیرند؛ فایل گواهی، کلید خصوصی و رمز در گفتگو یا مخزن قرار نمی‌گیرند. تا تهیه و آزمون روش واقعی، انتشار با `signed=false` ادامه دارد.
