# راهنمای استفاده از افزونه Paasta

## ورود امن

آیکن پاستا را در Activity Bar باز کنید و در بخش «حساب پاستا» روی «ورود امن با مرورگر» بزنید. وضعیت اتصال در Status Bar پایین VS Code هم قابل مشاهده و کلیک است. فرمان `Paasta: ورود امن` در Command Palette نیز به‌عنوان مسیر جایگزین باقی مانده است.

افزونه یک درخواست ده‌دقیقه‌ای می‌سازد، کد را در Clipboard قرار می‌دهد و صفحه تأیید پاستا را باز می‌کند. نام دستگاه باید `Paasta VS Code` باشد. پس از تأیید، Token در SecretStorage خود VS Code ذخیره می‌شود.

اگر عضو چند فضای کاری هستید، Token برای فضای کاری فعال هنگام تأیید ساخته می‌شود. برای تغییر فضا، در کنسول فضای فعال را تغییر دهید، از افزونه خارج شوید و دوباره وارد شوید.

## فهرست و وضعیت پروژه‌ها

نمای «پروژه‌ها» در پنل اختصاصی پاستا وضعیت آماده، در حال استقرار یا متوقف را نشان می‌دهد. روی پروژه کلیک کنید یا `Paasta: وضعیت پروژه` را اجرا کنید تا آخرین Build، Stack و زمان ثبت آن دیده شود. برای اطلاعات تازه، فرمان Refresh را بزنید.

## مشاهده لاگ

`Paasta: مشاهده لاگ پروژه` تعداد ۳۰۰ خط آخر لاگ Runtime نمونه فعال را در یک سند موقت باز می‌کند. اگر نمونه هنگام Rollout جایگزین شده، View را تازه و دوباره تلاش کنید. Current/Previous logs و Build logs کامل در صفحه Deployment کنسول قرار دارند.

## ساخت و ویرایش کد با Paasta Code

1. پوشه پروژه را در یک Workspace مورداعتماد VS Code باز کنید و وارد پاستا شوید.
2. در نمای «شروع» روی «بازکردن Paasta Code» بزنید. گفتگو در یک تب مستقل Editor باز می‌شود.
3. مدل را از سربرگ چت انتخاب کنید و نتیجه موردنظر را در Composer پایین تب بنویسید.
4. روند تحلیل و ساخت داخل همان گفتگو به‌صورت زنده دنبال می‌شود.
5. پس از آماده‌شدن پاسخ، از فهرست چندانتخابی فقط فایل‌هایی را که می‌خواهید اعمال شوند انتخاب کنید. نخستین فایل انتخاب‌شده در Diff بومی VS Code باز می‌شود و تأیید نهایی تعداد فایل‌های پذیرفته و ردشده را نشان می‌دهد.
6. تصمیم هر فایل برای همان درخواست در نشست پایدار Paasta Code ثبت می‌شود. بستن پنجره تأیید هیچ فایلی را تغییر نمی‌دهد.

در نخستین استفاده، افزونه درباره ارسال فایل‌های پروژه به Workspace اختصاصی شما در پاستا تأیید می‌گیرد. مسیرهای حساس و حجیم مانند `.env`، کلیدها و گواهی‌های خصوصی، `.git`، `node_modules` و خروجی Build ارسال نمی‌شوند. با این حال، قبل از ادامه مطمئن شوید هیچ راز یا داده مشتری در فایل‌های عادی پروژه قرار نگرفته است.

این نسخه فایل‌های موجود را ویرایش و فایل جدید ایجاد می‌کند، اما فایلی را صرفاً به دلیل نبودن در پاسخ مدل حذف نمی‌کند. برای بازبینی تغییرات بزرگ، ابتدا Commit یا نسخه پشتیبان محلی داشته باشید.

## Cost Preview

پیش‌نیاز این فرمان نصب Paasta CLI است. ورود امن افزونه، CLI را نیز بدون نمایش یا نوشتن Token متصل می‌کند:

```text
paasta version
```

پوشه پروژه را به‌عنوان Workspace اصلی باز و `Paasta: بررسی هزینه استقرار` را اجرا کنید. CLI نوع پروژه، ناحیه، پلن و شیوه پرداخت را بررسی می‌کند، هزینه و حداقل اعتبار را نشان می‌دهد و پیش از ساخت منابع منتظر تأیید می‌ماند. برای استفاده صرفاً به‌عنوان پیش‌نمایش، تأیید نهایی را انجام ندهید.

## استقرار پوشه فعلی

دکمهٔ اصلی «انتشار روی پاستا» در ابتدای پنل همان `paasta deploy <workspace>` را با ProcessExecution امن VS Code اجرا می‌کند. پرسش‌ها، هزینه و پیشرفت Build در ترمینال نمایش داده می‌شوند. فرمان `Paasta: استقرار پوشه فعلی` نیز همین مسیر را از Command Palette اجرا می‌کند.

در Workspace چندریشه‌ای، نسخه 0.1.0 پوشه اول را Deploy می‌کند. برای مسیر دیگر، آن پوشه را در یک Window جدا باز کنید یا دستور CLI را مستقیم اجرا کنید.

## Rollback

1. فرمان `Paasta: بازگردانی نسخه` را اجرا کنید.
2. پروژه و یکی از Buildهای موفق را انتخاب کنید.
3. شناسه نسخه را در پیام تأیید بررسی کنید.
4. فقط در صورت اطمینان «بازگردانی» را بزنید.

Rollback داده‌های متصل را حذف نمی‌کند و بدون Build دوباره، Image نسخه انتخابی را منتشر می‌کند. نسخه جاری تا آماده‌شدن Rollout مقصد حفظ می‌شود. تغییرات ناسازگار دیتابیس یا متغیرهای محیطی همچنان باید توسط تیم برنامه بررسی شوند.

## خروج و لغو دسترسی

`Paasta: خروج` Token محلی را از SecretStorage حذف می‌کند. برای بی‌اعتبارکردن Token در سمت سرور نیز وارد صفحه API Token کنسول شوید و ورودی `Paasta VS Code` را لغو کنید.
