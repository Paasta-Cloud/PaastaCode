# Paasta for VS Code

افزونه رسمی پاستا برای استقرار، مشاهده وضعیت و بازیابی پروژه‌ها بدون خروج از VS Code.

> نسخه `0.8.5` یک Public Preview است. عملیات حذف پروژه یا منابع عمداً در این نسخه وجود ندارد.

نسخهٔ `0.8.5`، پاستاکد کامل و ابزارهای پاستا را با شناسهٔ واحد `paasta-cloud.paasta` و یک پنل ارائه می‌کند. موتور ایجنت، تسک‌ها و تأیید ابزارهای پاستاکد حفظ می‌شوند. بسته‌های بومی از مسیر بسته‌بندی پاستاکد ساخته می‌شوند و موتور و Node را همراه دارند؛ در Web IDE رایگان، اجرای ابزارهای بومی با اتصال اختیاری به دستگاه خودتان انجام می‌شود. بستهٔ هر معماری پیش از انتشار در VS Code واقعی آزمایش می‌شود. نشانی دانلود قدیمی ۰٫۷ برای سازگاری حفظ شده است.

در نسخهٔ یکپارچهٔ آنلاین، ورود پاستاکد هم از نشست کنسول است؛ فعال‌کردن مصرف AI و تعیین سقف آن همچنان انتخاب کاربر است. اطلاعات حساب و گفتگوهای قبلی دسکتاپ در `~/.paastacode` حذف نمی‌شوند. افزونهٔ قدیمی `paasta.paastacode` پس از نصب بستهٔ یکپارچه لازم نیست؛ به‌روزرسان داخلی نیز آن افزونهٔ جدا را دوباره نصب نمی‌کند.

در محیط آنلاین شخصی، سورس پروژه‌های Git، آپلودی و قالب‌ها در اولین ورود در پوشه‌های مستقل آماده می‌شود؛ دریافت دوباره فایل‌ها و تغییرات قبلی را بازنویسی نمی‌کند. پروژه‌های ساخته‌شده فقط از Image سورس قابل دریافت ندارند. پنل پاستا خودکار فعال می‌شود و برای این محیط شخصی، Workspace Trust جداگانه لازم نیست؛ اعتماد VS Code دسکتاپ تغییر نمی‌کند. دستور `paasta` در ترمینال از همان نشست کنسول استفاده می‌کند و ورود جداگانه ندارد. دسترسی در هر اجرای CLI از مجوز تازه خوانده می‌شود؛ خروج از کنسول یا انقضای نشست، دسترسی را پایان می‌دهد. برای پروژهٔ Git، حساب متصل باید متعلق به خودتان باشد. کلید Git در فایل‌های پروژه ذخیره نمی‌شود. مصرف AI و انتشار برنامه همچنان تأییدهای خود را دارند.

در محیط آنلاین، پنل پاستا و پاستاکد به‌صورت پیش‌فرض در سمت راست و با فضای بیشتر باز می‌شوند؛ اندازه و جای انتخاب‌شدهٔ شما در ورودهای بعدی حفظ می‌شود. یک فایل از پروژه را باز کنید تا همان پروژه برای پاستاکد و ابزارهای پاستا انتخاب شود. اتصال GitHub یا GitLab و شاخهٔ انتشار هر پروژه از تنظیمات همان پروژه خوانده می‌شود؛ اتصال پروژهٔ دیگر به آن منتقل نمی‌شود.

## نصب

1. بستهٔ مناسب سیستم‌عامل و پردازنده را از [صفحه رسمی افزونه در مستندات پاستا](https://paasta.cloud/docs/vscode) دریافت کنید.
2. در VS Code پنجره Extensions را باز کنید.
3. از منوی `…` گزینه `Install from VSIX…` را بزنید.
4. فایل دانلودشده را انتخاب و در صورت درخواست VS Code را Reload کنید.

نصب از ترمینال:

```text
code --install-extension paasta-vscode-0.8.5-win32-x64.vsix
```

## شروع سریع

1. آیکن پاستا را در Activity Bar باز و در بخش «حساب پاستا» روی «ورود امن با مرورگر» کلیک کنید.
2. کد یک‌بارمصرف خودکار کپی و صفحه تأیید در مرورگر باز می‌شود.
3. پس از تأیید، حساب، Paasta Code و پروژه‌ها در پنل اختصاصی پاستا آماده‌اند. وضعیت اتصال در Status Bar هم همیشه دیده می‌شود.
4. پوشه برنامه را باز کنید و در بالای پنل پاستا روی دکمهٔ اصلی «انتشار روی پاستا» بزنید. افزونه نشست CLI را از همان ورود امن آماده می‌کند؛ تنظیمات، هزینه و تأیید نهایی در Terminal دیده می‌شوند.
5. برای توسعه با AI روی «بازکردن Paasta Code» بزنید؛ گفتگو در یک تب مستقل Editor باز می‌شود.

راهنمای کامل در [USAGE.md](USAGE.md) و رفع خطا در [TROUBLESHOOTING.md](TROUBLESHOOTING.md) قرار دارد.

## قابلیت‌ها

- ساخت و اصلاح پروژه با Paasta Code و انتخاب مدل از Backendهای فعال ادمین
- نمایش زنده مراحل تحلیل و ساخت فایل‌ها در Output اختصاصی
- انتخاب فایل‌به‌فایل، بازبینی در Diff خود VS Code و ثبت نتیجه تأیید یا رد هر فایل
- حذف خودکار فایل‌های حساس، باینری و پوشه‌های build از زمینه ارسالی به مدل
- ورود Device Flow بدون واردکردن Token در VS Code
- نگهداری Token فقط در `SecretStorage` سیستم
- فهرست پروژه‌ها و آخرین وضعیت استقرار
- مشاهده ۳۰۰ خط آخر لاگ اجرا در یک سند موقت
- Deploy پوشه فعلی با CLI رسمی پاستا
- نمایش هزینه در جریان تأیید CLI، پیش از ساخت منابع
- Rollback به Build موفق با انتخاب نسخه و تأیید صریح
- بازکردن پروژه در کنسول پاستا

## پیش‌نیاز Deploy

دستورهای مشاهده پروژه، Status، Logs و Rollback مستقیماً از API استفاده می‌کنند. برای Deploy و Cost Preview باید Paasta CLI نصب باشد. افزونه با Token امن خودش نشست CLI را پیش از انتشار آماده می‌کند و نیازی به اجرای جداگانهٔ `paasta login` نیست.

Linux و macOS:

```sh
curl -fsSL https://console.paasta.cloud/install.sh | sh
```

Windows PowerShell:

```powershell
irm https://console.paasta.cloud/install.ps1 | iex
```

## تنظیمات

- `paasta.server`: آدرس کنسول؛ مقدار پیش‌فرض `https://paasta.cloud` است.
- `paasta.cliPath`: مسیر فایل اجرایی CLI؛ مقدار پیش‌فرض `paasta` است.

برای حساب Production مقدار `paasta.server` را تغییر ندهید. تغییر این گزینه فقط برای محیط توسعه یا نصب اختصاصی مناسب است.

## امنیت و حریم خصوصی

- افزونه رمز، OTP یا API Token را در Settings، فایل پروژه یا Log نمی‌نویسد.
- دسترسی Token براساس نقش شما در فضای کاری صادر می‌شود و از صفحه API Token کنسول قابل لغو است.
- Rollback بدون انتخاب Build و تأیید Modal اجرا نمی‌شود.
- Deploy و Cost Preview از CLI رسمی استفاده می‌کنند و فایل‌های حساس مانند `.env`، کلید خصوصی، `.git` و `node_modules` را در Archive قرار نمی‌دهند.
- جزئیات کامل در [SECURITY.md](SECURITY.md) آمده است.

## توسعه

پوشه `extensions/paasta-vscode` را در VS Code باز و `F5` را اجرا کنید.

```text
npm test
npx @vscode/vsce package
```

## بازخورد

خطا یا پیشنهاد را در [GitHub Issues](https://github.com/Paasta-Cloud/paasta/issues) همراه نسخه VS Code، نسخه افزونه و مراحل بازتولید ثبت کنید. Token، Secret، محتوای `.env` یا لاگ دارای اطلاعات شخصی را ضمیمه نکنید.
# نسخهٔ ۰.۶

نسخهٔ در حال توسعه، داخل بستهٔ [محیط کدنویسی محلی](../../deploy/code-workspace/README.md) قرار می‌گیرد؛ فایل دانلود عمومی فعلاً همان نسخهٔ منتشرشدهٔ قبلی است.

- «دریافت سورس پروژه»: سورس نگه‌داری‌شدهٔ نسخهٔ فعال پروژهٔ آپلودی را در پوشهٔ خالی باز می‌کند؛ Python 3 لازم است. این فرمان به API جدید سمت سرور نیاز دارد و تاریخچهٔ Git را از ZIP بازسازی نمی‌کند.
- «انتقال پروژه به Git»: ساخت مخزن خصوصی از صفحهٔ GitHub/GitLab یا انتخاب مخزن خصوصی خالی، بررسی سورس و تاریخچه، اولین کامیت برای پروژهٔ بدون گیت و پوشِ بدون بازنویسی تاریخچه. Token نوشتن مخزن فقط برای همان انتقال استفاده می‌شود و در تنظیمات ذخیره نمی‌شود.
- پس از پوش موفق، اتصال مخزن به پروژهٔ پاستا با انتخاب حساب متصل و تأیید جداگانه انجام می‌شود. اتصال به API جدید نیاز دارد؛ نسخهٔ فعال سرویس تغییر نمی‌کند و انتشار خودکار خاموش می‌ماند.
- پاسخ AI روی فایل تغییرکرده، فایل ذخیره‌نشده یا فایل تازه‌ساخته‌شده توسط کاربر اعمال نمی‌شود.

بررسی خودکار فقط نشانه‌های شناخته‌شدهٔ اطلاعات محرمانه را پیدا می‌کند؛ پیش از انتقال، فایل‌ها و تاریخچه را خودتان هم بازبینی کنید. نسخهٔ محلی جای سرویس چندکاربره با جداسازی تأییدشده را نمی‌گیرد.
