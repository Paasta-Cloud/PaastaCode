# مدل امنیت افزونه Paasta

## احراز هویت

تأیید ورود در مرورگر انجام می‌شود و افزونه Password یا OTP دریافت نمی‌کند. Token به User، Tenant و نقش تأییدشده محدود است، در VS Code SecretStorage ذخیره می‌شود، در Settings یا فایل پروژه نوشته نمی‌شود و از صفحه API Token کنسول قابل لغو است.

## مرز دسترسی پروژه

Project List، Deployment History، Logs و Rollback از APIهای Tenant-aware پاستا استفاده می‌کنند. سرور در هر درخواست Token، Scope و دسترسی پروژه را دوباره بررسی می‌کند. افزونه Namespace، Kubeconfig یا Credential زیرساخت دریافت نمی‌کند.

## عملیات تغییردهنده

نسخه 0.2.0 علاوه بر Rollback، فایل‌های پیشنهادشده توسط Paasta Code را فقط پس از نمایش بازبینی و تأیید Modal روی Workspace محلی اعمال می‌کند. در اولین استفاده، ارسال Source به فضای کاری پاستا صریحاً تأیید می‌شود و Workspace باید Trusted باشد. فایل‌های متنی مجاز در Workspace ایزوله همان مشتری ذخیره و به Backend انتخاب‌شده فرستاده می‌شوند. فایل‌های `.env`، کلید خصوصی، تنظیمات Registry، فایل‌های باینری و پوشه‌های dependency/build ارسال نمی‌شوند. هر درخواست به ۸۰ فایل متنی و مجموع ۷۰۰ کیلوبایت محدود است. حذف پروژه، Volume، Database، Secret یا Token در افزونه وجود ندارد.

Deploy از CLI رسمی اجرا می‌شود. CLI هزینه را پیش از ایجاد منابع نشان می‌دهد و فایل‌های حساس شناخته‌شده را از Archive کنار می‌گذارد. Token CLI مستقل از Token افزونه نگه‌داری می‌شود.

## گزارش آسیب‌پذیری

Secret یا جزئیات آسیب‌پذیری را در Issue عمومی قرار ندهید. از کانال پشتیبانی داخل کنسول استفاده و فقط اطلاعات Sanitized ارائه کنید.
# مرزهای پیش‌نمایش محلی ۰.۶

انتقال به Git فقط در Workspace مورداعتماد انجام می‌شود. مخزن مقصد باید HTTPS روی GitHub/GitLab، خصوصی و خالی باشد؛ تکرار انتقال همان کامیت پذیرفته می‌شود. پوش اجباری، اجرای Hookها، ارسال Tagها و پوش بازگشتی Submoduleها غیرفعال است. تنظیمات محلی سفارشی URL/HTTP/Credential/Push مانع انتقال می‌شوند. اعتبارنامهٔ موقت فقط در حافظه و محیط فرایندهای همان انتقال قرار دارد و فایل Askpass شامل Token نیست؛ فایل‌های موقت بعد از عملیات حذف می‌شوند. کدها و افزونه‌های همان کاربر می‌توانند قابلیت‌های او را مصرف کنند؛ این مکانیزم Sandbox نیست و نباید Token عمومی حساب یا رمزهای محیط اصلی را به آن داد.

برای پروژهٔ بدون Git، فایل‌های خصوصی شناخته‌شده و خروجی‌های تولیدشده کنار گذاشته می‌شوند و قواعدشان به `.gitignore` افزوده می‌شود. تاریخچهٔ موجود بازنویسی نمی‌شود؛ یافتن مسیر حساس یا نشانهٔ شناخته‌شدهٔ Secret در تاریخچه، انتقال را متوقف می‌کند. بازبینی خودکار تضمین نبودن همهٔ انواع Secret نیست.

API دریافت سورس، مجوز نوشتن همان پروژه و Scope استقرار را بررسی می‌کند و فقط آرشیو منقضی‌نشدهٔ Build آماده با Image فعال را برمی‌گرداند. API اتصال Git، مجوزهای Git و استقرار، تعلق حساب متصل و کامیت مقصد را دوباره بررسی می‌کند؛ تغییر منبع و Audit در یک تراکنش ثبت می‌شوند. هیچ Namespace، Build، Webhook، شارژ یا استقرار خودکاری ایجاد نمی‌شود.

این نسخه هنوز از Device Flow فعلی استفاده می‌کند و توکن کوتاه‌عمر محدود به محیط/پروژه برای میزبانی چندکاربره آماده نشده است. بستهٔ محلی فقط به localhost متصل می‌شود؛ عرضهٔ میزبانی‌شده به تأیید Sandbox، ورود یکپارچه، بازیابی و حسابداری نیاز دارد.

تنظیمات سرور حساب و مسیر CLI فقط از تنظیمات کاربر خوانده می‌شوند؛ تنظیمات داخل پروژه نمی‌توانند مقصد توکن یا فایل اجرایی را عوض کنند. توکن افزونه فقط برای سرور صادرکننده استفاده می‌شود و درخواست احراز هویت‌شده Redirect را نمی‌پذیرد. اجرای CLI به Workspace مورداعتماد نیاز دارد. فایل موقت Askpass در پوشهٔ خصوصی خانه ساخته و پس از انتقال حذف می‌شود؛ توکن داخل فایل نیست. برای پوش‌های بعدی Git باید روش ورود خودتان را تنظیم کنید.
